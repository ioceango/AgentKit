# 03 软件工程原则

可判定的工业化原则。技术栈细节写在 overlay 的 `architecture.md`。

## 单一职责与最少知识

- 一个模块一个理由去改。出现「既编排业务又拼 SQL 又写 HTTP」必须拆。
- 调用方只依赖对方的公开契约，禁止够到内部结构或全局可变状态传参（经封装的请求上下文除外）。

## 显式失败

- 失败必须能区分：调用方错 / 本服务错 / 下游错 / 可重试。禁止全部变成同一内部错误。
- 对外文案说明能否重试和下一步；对内日志保留分类。

## YAGNI 与扩展

- 不为假想需求预开抽象层。第二次出现再抽。
- 真要扩展时，优先加稳定接口上的实现，而不是复制一套旁路。

## 配置与代码分离

- URL、超时、限额、功能开关、密钥一律来自配置，并在样例文件里有说明。
- 禁止把密钥写进源码、镜像或提交。

## 事务与副作用边界

- 本地数据事务不得跨越网络调用、对象存储或模型推理。先拿数据或先写意图，再调外部，再短事务落结果。

## 检查

| 原则 | 不合格信号 |
|------|------------|
| SRP | 一个文件同时改「展示、领域、存储」三处理由 |
| 显式失败 | 所有 except 都变成 500 / 通用 toast |
| YAGNI | 无调用方的策略接口、空实现 |
| 配置分离 | 业务函数字面量里出现主机名或超时毫秒 |
