# 06 自动化测试流程

栈命令写在 `.agents/verification.md` §1.1。本文不绑定某包管理器。

## 顺序

1. `bash scripts/verify-agent.sh`（文档门禁）通过之前，禁止宣称完成，也禁止进入代码验证。
2. 静态检查 → 单元/集成 → 构建（若有）→ 有 UI 则端到端。
3. 任一步失败从该步重跑。同一问题修 3 次仍失败则停止并报告阻塞。

## 必须

- Bug 修复至少一条回归，注释含 `BUG-NNN`。
- 外部模型、付费 API、真实短信/邮件网关一律 mock。
- 覆盖正常路径、边界、错误分类与可重试性、脱敏（日志断言不包含密钥/正文全量）。
- 模块解析失败（找不到模块）为零容忍。

## 有 UI 的 FEAT / BUG

- 必须跑端到端（优先 Playwright；MCP 没有则用项目内 CLI）。
- 截图只放该迭代 `test-report/S<2位>-<slug>.png`，从 S01 连续。
- `test-report.md` 用表引用每一张：编号、路径、覆盖的 AC、画面说明。
- 禁止用 curl、读代码、单张未操作截图代替。
- 零 UI 迭代：在 checklist 写豁免理由并获确认。

## 报告红线

只允许填写真实执行结果。禁止「预计通过」。未执行步骤必须写未执行。
