# 10 上下文与 tokens 消耗控制

目标：模型只带**该步需要的执行口径**，细则按需打开，避免指针和对话被全文撑满。

## 分层读取

| 先读 | 不要一上来读 |
|------|----------------|
| `.agent/` 七份里与当前任务相关的那些 | 把 `docs/rules/01–10` 全部贴进指针或系统提示 |
| 当前 FEAT/BUG 的 spec/plan | 无关迭代目录 |
| 用搜索定位符号再打开文件片段 | 整仓 dump |

指针文件（`AGENTS.md`、`CLAUDE.md`、`.grok/rules`、`.trae/rules`）只保留：这是谁的入口、必读清单、验证命令、冲突以 `.agent/` 为准。禁止出现条款列表或 `## 关键红线摘要`。

## 工作方式

- 改规则只改 `.agent/` 或对应 `docs/rules/0X`，不要在工具目录再抄一份。
- Skill 写步骤和检查表，不把 `.agent/` 全文嵌进去。
- 日志、test-report、commit message、issue 正文禁止粘贴 prompt 全文、密钥、业务正文。
- 大文件：先搜符号/标题，再读窗口；禁止为了「全面」一次性读入超大生成物。

## 安装器与门禁

- 安装器替换的占位符只有产品名、slug、套件版本、MCP 路径，不把 overlay 全文写入指针。
- 门禁检查指针「含 `.agent/` 且不含红线摘要」，不把十条细则是否被模型读过当作门禁（读不读由任务决定）。

## 不合格信号

- 指针超过一屏还在复述 constraints。
- 一次对话为了小改动附上全部 rules。
- 为省事把密钥或 prompt 丢进仓库「方便重放」。
