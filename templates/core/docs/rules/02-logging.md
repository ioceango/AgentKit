# 02 日志规范

目标：一次失败能凭关联 id 还原路径，且日志里没有密钥和业务正文。

## 分级

| 级别 | 何时 | 生产 |
|------|------|------|
| DEBUG | 细节、耗时、入参摘要（已脱敏） | 仅调试开关打开时 |
| INFO | 成功路径上的里程碑 | 是 |
| WARNING | 可自愈、可重试、客户端输入不合法 | 是 |
| ERROR | 用户可感知的失败，需人看 | 是 |
| CRITICAL | 进程/依赖级不可用 | 是 |

## 必须

- 关键路径带同一请求关联 id（名称自定，全链路一致）。
- 同一次失败只在转化为对外错误的那一层打一条 ERROR，下层用 WARNING/DEBUG，禁止逐层重复。
- ERROR 保留可定位信息（关联 id + 阶段 + 分类）。禁止空 catch。
- 用户输入不合法用 WARNING，不要抬成 ERROR。

## 禁止写入日志

密钥、完整个人身份、签名 URL、业务正文全量、prompt 全文、文件二进制/Base64。长文本只记长度与摘要特征。

## 禁止

- `print` 当日志。
- 业务代码里自行删除或改写日志文件。
- 把上游原始报文或堆栈返回给终端用户。
