# 01 代码规范

与业务、语言目录名无关。执行阈值以 `.agent/rules.md` 为准。

## 必须

- 一个函数只做一件事；超过 `.agent/rules.md` 行数/参数/嵌套上限必须拆分或在该迭代 `plan.md` 书面豁免。
- 禁止靠压行、删空行、合并语句把超标文件「压」进上限。
- ≥ 8 行重复必须抽取。禁止无调用方的函数、组件、类型。
- 禁止保留注释掉的旧实现和无用导入。
- 命名用完整语义词，禁止 `data2`、`tmpX`、`handle3`。
- 注释只写**为什么**（取舍、边界、坑），不复述代码在做什么。
- 每个导入必须能解析；新增路由与页面必须同批次落地。
- 校验以后端（或权威服务端）为准，客户端只做体验前置，禁止两套互相偏移的规则。

## 禁止

- 为了演示感堆砌无用户路径的代码。
- 在业务代码里硬编码 URL、超时、限额、路径、密钥（配置规范见工程原则；样例文件见部署规范）。
- 把「先能跑」的草稿当完成态留下。

## 检查

| 问 | 不合格 |
|----|--------|
| 这个函数还能用一句话说清吗？ | 说不清或超过行数上限 |
| 删掉这段有没有调用方失败？ | 没有 → 死代码 |
| 同一规则前端后端是否同一出处？ | 各写一套 |
