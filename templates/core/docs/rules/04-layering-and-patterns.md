# 04 分层与设计模式原则

目录名随项目，**方向**不变。具体包路径写在 overlay `architecture.md`。

## 单向分层

推荐后端四层（可改名，禁止反向依赖）：

`接口层 → 领域/应用服务 → 数据访问 → 数据模型`

| 层 | 只做 | 禁止 |
|----|------|------|
| 接口 | 校验、鉴权注入、错误到协议语义、组装响应 | 领域规则、直接碰 ORM/SQL、调外部 IO |
| 服务 | 编排、规则、事务边界 | 读 HTTP 请求对象、裸 SQL |
| 数据访问 | 参数化读写 | 业务判断、自行提交事务（plan 声明的幂等写除外） |
| 模型 | 结构与用途注释 | 业务逻辑、协议、外部调用 |

前端（若有）：页面编排、组件展示、状态钩子、无 UI 的领域/HTTP 封装分开放。页面禁止散落裸 HTTP。

禁止为了绕过某层再开平行包长期承载业务。

## 何时用常见模式（不要为模式而模式）

| 模式 | 何时用 | 何时不用 |
|------|--------|----------|
| 仓储 | 同一聚合有多种查询/写入，要单测时假存储 | 只有一两句 CRUD 却做完整仓储接口 |
| 适配器 | 认证、存储、模型供应商会换 | 项目只有一个实现还做三层接口 |
| 策略/注册表 | 多个算法或供应商按配置选一个 | 两个 if 就能说清却上策略框架 |
| 门面 | 给 UI 一条稳定用例入口 | 门面里又堆领域规则 |

新能力落在已有稳定接口上。换供应商时改适配器，不改主用例流程里的 `if provider ==`。
